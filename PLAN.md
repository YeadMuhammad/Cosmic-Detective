# Cosmic Detective: Roadmap

1. **Presentation front end (done).** Title screen, campaign case board (5 chapters, 50 cases), investigation screen with Blink Comparator and Difference Imaging on real NASA SkyView plates, visible verification pipeline, debrief with XP and rewards, rank-up celebration, rankings, dossier, mission briefing, settings, 7-step guided tutorial on Barnard's Star, dark/light/Okabe–Ito modes, presenter controls (Shift+P).
2. **SPHEREx live-data foundation.** Milestones, in order:
   - [x] **Step 0 — CORS and cutout spike.** A real QR2 MEF cutout responds to GET and includes the required extensions. Direct browser CORS is not relied upon; the existing Netlify proxy is extended for restricted cutout access, and FITS processing stays out of the archive function.
   - [x] **Browse viewer (public, display-only).** Guest users can enter RA/Dec and FOV, persist URL state (`?ra=&dec=&fov=`), render FITS IMAGE cutouts, and play returned observations. Frames retain date, detector, release, and band labels; scientific comparison tools remain disabled. `frame-ancestors` headers allow approved Netlify embeds. Squads remain optional.
   - [x] **Metadata capability contract.** The portal derives `available | unavailable | computing`-shaped capability records and reason codes from returned observation metadata for Blink, Difference, Light Curve, Phase fold, and Spectrum. Same-channel time-series requirements remain separate from cross-channel spectrum metadata, and browse mode keeps scientific comparison tools disabled.
   - [x] **Metadata registry and acceptance fixtures.** Extend the IRSA adapter to group observations by footprint, detector, channel, processing release, survey pass, and time; evaluate wavelength at the target pixel; and generate a registry from timestamped archive metadata snapshots, seeded with deep fields, ecliptic-pole regions, and Barnard's Star, Epsilon Indi B, WISE 0855, RW Aurigae, and R Draconis. Add per-target acceptance fixtures whose expected capabilities are derived from the snapshot, not hand-asserted.
   - [x] **Explicit cached snapshot mode.** Users can select `Cached snapshot (date)` explicitly, with a persistent `provenance.origin: 'cached-live'` banner and timestamp. It never automatically replaces unavailable live data or generated images.
   - [x] **Cached snapshot demo path.** Presenter controls include an explicit cached SPHEREx demo route with `source=cached`; it does not alter live mode or silently fall back.
   - [x] **Worker, jobs, and cache.** Run Astropy/Photutils/reproject processing outside Netlify Functions; Netlify/Supabase orchestrate jobs, rate-limit coordinate queries, and expose `computing`. Use a Python worker and object storage near IRSA. Verify cutout support before downloading full MEFs. Version cache keys by release, observation, detector, cutout geometry, and processing parameters. Worker failure becomes `unavailable` with a reason.
   - [ ] **Native-pixel forced photometry (not enabled; worker fails closed).** Use calibrated IMAGE/FLAGS/VARIANCE inputs, the documented spatial PSF/ePSF zone at the source position, detector solid-angle map, and science-grade CWAVE/CBAND calibration. Model local background without subtracting ZODI twice. Propagate pixel, background, and calibration uncertainties; expose flags, fit quality, and upper limits. Pass injection/recovery tests and validate representative measurements against the IRSA Spectrophotometry Tool before marking usable. The earlier prototype's wavelength-based PSF selection and WCS-estimated pixel area were removed because they could produce scientifically invalid measurements.
   - [ ] **Validated IRSA measurement import and light curve (implementation in progress).** Accept official IRSA Spectrophotometry VOTable exports only when one unambiguous table has the required schema and units, including source flux/uncertainty in µJy and background surface brightness `flux_bkg` in MJy/sr, and target position, QR2/QR3 release, detector, exposure ID, Deep Field indicator, MJD, flags, and fit quality validate. Require all photometry rows to resolve to one target position within 0.1 arcsec and match the portal coordinate within 6 arcsec using great-circle separation. Reject query errors and truncated (`OVERFLOW`) exports. Permit structurally valid exports with zero analysis-eligible points for inspection, but keep tools disabled unless approved rows pass their capability gates. Admit only IRSA's documented nominal flag values 0 or SOURCE-only (`2097152`); exclude all other flags until their effects have explicit treatment. Let researchers set an optional fit_ql ceiling, with no default cutoff, and apply it consistently to light-curve and phase-fold gates while retaining excluded rows for review. Reset target-specific fit_ql, exposure class, passband, and trial-period selections when a new export is imported. Group curves within one detector/release/exposure class and matching central wavelength plus effective bandwidth (export precision 0.0001 µm); keep Deep Field and wide-survey measurements separate pending cross-class calibration validation. Keep imported provenance visible, expose excluded flagged rows for review, show the separate background trend, disclose that position and morphology are fixed inputs to IRSA photometry, and label that per-point errors omit shared calibration covariance. Review `ext_flg` and `nyquist_comp` definitions and actual export presence against the Explanatory Supplement; preserve and gate any relevant diagnostics before marking the importer complete. Confirm the actual IRSA VOTable serialization; support or clearly reject each emitted format. Add a representative downloaded IRSA export fixture and validate parser behavior before marking complete.
   - [ ] **Spectrum (disabled pending time-coherent grouping).** Do not treat points from different exposure times as one spectrum. Group a spectral epoch from the official exposure/visit lineage, preserve wavelength, bandwidth, flags, release, and covariance/systematics, then verify the grouping on real IRSA outputs before enabling. Keep QR2 and QR3 calibration lineages separate unless an official correction is applied and tested.
   - [ ] **Phase fold (conditional UI implemented; validation pending).** Require a validated same-detector, same-release live series, positive trial period, at least six measurements spanning two cycles, uncertainty-weighted bins, and null-model comparison. Phase zero is the first valid observation. Describe output as a trial-period fold; the raw weighted χ² reduction is descriptive and does not account for added bin parameters or period trials, so it is not a significance or false-alarm probability. The comparison also omits shared calibration covariance. Do not present a false-alarm probability until the period-search/trial-factor calculation is independently validated. Outputs must never claim a confirmed discovery.
   - [ ] **Image comparison (not enabled; comparison contract alone is insufficient).** Implement spatial reprojection with flux/variance propagation, quality masks, calibration/wavelength matching, proper-motion-aware source positions, and empirically validated astrometric residuals. PSF-match before difference imaging; include resampling covariance and registration uncertainty. Pass blank-sky false-positive and injected-source recovery tests before exposing difference significance. Do not treat channel identity as wavelength equivalence or combine QR2/QR3 without a documented correction.
   - [ ] **Archive validation and extensibility.** Add contamination/quality metadata, optional Gaia/WISE overlays, on-demand spectra, and release adapters without hard-coded collections. Rank gates progression and rewards only; scientific availability always comes from the capability response.
3. **Player accounts and progress.** Supabase Auth and Postgres/RLS cloud saves are implemented; retain guest localStorage play and document account work as maintenance/expansion rather than a Netlify migration.
4. **Verification service.** Server-side stationary, blend/halo and catalogue cross-match checks.
5. **Consensus and live leaderboards.** Weighted agreement per Section 5.4; replace demo players.
6. **Chapters 3–5 tools.** Chapter 3 Multi-band compositor with sector map (case 21, real DSS/2MASS/WISE Barnard's Star sector) and Chapter 4 Light Curve Analyzer (case 31, modelled curves; import real photometry with `scripts/import-lightcurve.mjs`) are in. Remaining: more registered sectors (`scripts/fetch-bands.mjs`), real archival curves, and the Chapter 5 research suite with candidate export; live SPHEREx capabilities are tracked in item 2.
7. **Authoring the remaining cases** (levels 5–50) and Chapter 5 live tiles.
